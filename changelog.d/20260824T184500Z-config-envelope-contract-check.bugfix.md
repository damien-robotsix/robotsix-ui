The config client now refuses a response that carries no `config` document instead of treating it as an empty config. A component whose `GET /config` spread its settings across the top level of the response handed the panel nothing to render, so every field fell back to its schema default and the operator's next Save wrote those defaults over the live config. `GET /config`, `PUT /config`, `POST /config/rollback` and `GET /config/versions` are all checked against the envelope `config-ownership.md` defines, a contract break raises the new `ConfigContractError`, and a save whose response is off-contract re-reads the config rather than re-rendering the form from a document it never received.
